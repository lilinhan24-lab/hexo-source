## 运行方式

访客填写邮箱 → 收到确认邮件 → 点击确认 → 加入专用名单。每封通知提供退订链接；退订状态由 Brevo 管理，代码不导入或重新订阅联系人。
静态网站只嵌入服务商表单，不存储读者邮箱。表单无法显示时提供直接打开入口。当前未配置额外 CAPTCHA；双重确认不等于完全防滥用。
通知工作流每小时第 17、47 分钟检查，GitHub 与服务商队列均可能延迟，不保证即时送达。

Hexo 输出 `email-notifications.json`，仅含已发布文章的标题、摘要、URL、日期及内容哈希，不包含正文或联系人。
- 正式发送只读取 https://www.han.tax/email-notifications.json ，不会发送本地未上线修改。
- 原始正文、标题、摘要或 `notify_revision` 改变会形成新通知版本。
- 仅修改 `updated`、重新构建、CRLF/LF 转换不会重发。仅替换图片时需手动更新 `notify_revision`。
- 草稿、未来文章、`notify: false` 不参与通知。
- 基线是首次启用时线上两篇文章的内容版本；不要随每次构建刷新，否则会吞掉通知。
- 使用确定性活动名称和 Brevo 历史记录去重，不使用免费账户禁止的 campaign tag。
- 已发送/排队版本跳过；草稿或不明确状态停止并提示检查。POST 不自动重试，避免重复发送。
- 无历史读取权限、无初始化基线、异常名单或一轮超过五篇变化均停止发送。
- 全员退订或名单为空时不创建活动。
- 保留底层 Atom 文件，但不向普通访客展示 RSS/XML 入口。

`email:templates` 生成本地样式预览，去除实际退订操作。

GitHub Actions：
- Secret：`BREVO_API_KEY`。
- Variable `HAN_EMAIL_TEST_ENABLED=true` 时可手动运行 test，只发往站长邮箱。
- Variable `HAN_EMAIL_SEND_ENABLED=true` 且工程 `enabled: true` 才允许正式通知。
- 暂停通知：关闭 `HAN_EMAIL_SEND_ENABLED`；撤下网页入口需再将工程 enabled 改 false 并发布。
- 不删除本站发送历史；不明确的活动先查实际状态，不能直接删草稿重跑。
- 不导入评论者邮箱，不将测试授权视为其他人的订阅同意。
